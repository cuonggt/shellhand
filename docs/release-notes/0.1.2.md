**SFTP can no longer delete a file on this Mac while it names a host.**
Pointing a pane at another host dropped its old connection before the new one
was open, but left the old listing on screen, and to the file window no
connection meant this Mac. A Delete made in that moment, or after the host
refused, went to the same path here — while the question named the host. Up to
0.1.1 that could take a file off this Mac's disk. A pane pointed at a host now
clears its listing at once, acts through that host's connection or not at all,
and a host that refuses keeps its name rather than the pane calling itself This
Mac.

**Deleting on this Mac moves to the Trash.** The file window removed a local
file for good, which no other Mac app does to a file you picked. It now goes to
the Trash, and the question says so: Move to Trash, and that you can put it
back. Deleting on a host is still final, and still says so.

**What goes wrong in the SFTP window stays on screen.** A rename, a new folder,
a delete or a path that failed with files listed said nothing at all: the
window only showed an error in place of an empty listing. It now says what
failed, and which file, in a banner over the listing until you dismiss it. A
folder on a host that is not empty explains why it stayed: SFTP deletes a
folder only once it is empty.

**Closing the SFTP window asks while files are still moving**, and so does
quitting, by the same switch in Settings ▸ General that asks before ending a
session. Both used to stop every transfer still going or waiting its turn
without a word.

**A group's menu acts on the group you clicked.** Right-clicking a group's card
in the grid and choosing Edit Group…, Delete Group… or New Group Inside… acted
on whichever group was selected before — Delete Group… on EU asked to delete
Production. Each item now carries the group it was opened on.

**The host editor keeps your edits when a save fails**, and says why inside
it, where it used to close and lose them. A tag still being typed when you
press Save is kept, as it would be on Return.

**The host list says what it holds, and how to get back.** A group counts every
host beneath it, so Production reads "7 hosts: 1 here, 6 in 2 groups" rather
than "1 host". An All Hosts row under the search field, and a path over an open
group — All Hosts › Production › EU — lead back up, where nothing did once a
group was open. The search field and the tags narrow the list in the middle as
well as the sidebar's, and it says so — "3 of 12 · tagged db" — with Show All
beside it.

**The menus act on what is in front.** With a terminal in front, ⌘B, the
toolbar's SFTP, Copy as ssh Command, Edit and Connect act on that terminal's
host, as ⌘T already did, rather than on whatever the sidebar had selected. ⌘↩
is the Host menu's alone.

**The inspector has something to say about more than a host.** A group shows
what it passes down to everything inside it — the user, the key, the jump host,
agent forwarding and colours, each marked with where it came from — and what is
inside it. A local shell says it is one. A machine typed into ⌘K shows where it
connects, with Save as Host…, which opens New Host filled in from what you
typed: there was no way to save one.

**One way of writing a destination.** `deploy@192.0.2.21:2222`, the way ssh is
typed, in the sidebar, the list, the inspector, ⌘K and the window's title,
which between them wrote it five ways. An inherited value says "from
Production" everywhere. What will run reads one argument a line, and Copy still
gives the whole command, quoted for a shell.

**A tab opened from ⌘K no longer repeats the port.** A machine typed with one
had a tab reading "root@127.0.0.1:1 — 1", the port taken for the folder the
shell was in, until the far end sent a title of its own.

Nothing else here is visible from the outside. The suite went from 643 checks
to 677, and every change to the code is now built and tested on a Mac at
GitHub as well as here — which found that Shellhand did not build with Xcode
26, and it does now.
