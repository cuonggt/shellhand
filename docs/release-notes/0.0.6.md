**New Local Shell opened at the root of the disk.** A shell started here
inherits the app's own working directory, and an app launched the ordinary way
— from the Dock, from Finder — has `/`. So a local shell opened at the root of
the disk rather than in your home directory, in every release up to 0.0.5. It
opens at home now, and the test for it asks the shell itself where it started
rather than reading the screen.

**A file pane could wait for ever.** Nothing in SFTP puts a limit on how long
a reply may take, and the app had nothing of its own either: a request the far
end never answered left a pane sitting on "Connecting…", or on a listing that
was never going to arrive. Worse, it could not even be asked again — the guard
that stops one pane opening twice was released at the end of the request, and
a request that never ends never reaches it. A request now gives up after half
a minute, says which kind of request went unanswered, and leaves the pane
showing that rather than nothing.

**Closing the SFTP window left its connections running.** Letting go of the
window released the window and the browser inside it, but not the `ssh` each
pane was talking through, so one connection per connected pane stayed open
until the app quit. Closing the window now ends them. If a question about
replacing files was still on screen when it closed, that is answered too —
Cancel, so nothing is carried on the way out — rather than leaving the copy
behind it waiting on an answer nobody could give any more.

Nothing else here is visible from the outside. The suite went from 403 checks
to 421, and what is new in it is the file browser's own orchestration — the
guard above, and the replace question driven against a copy genuinely parked
on it — along with the SFTP deadline and the two ends of a connection that
stops answering.
