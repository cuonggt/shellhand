**Symbolic links were left behind coming down, and carried wrongly going up.**
A folder dragged from a host onto this Mac arrived without any of its symlinks
at all. Sent the other way, a link to a file arrived as a full copy of that
file, a link to a folder arrived as a folder with nothing inside it, and a
link pointing at something that is not there arrived not at all — each of them
without a word, while the transfer reported success. A link is now carried as
a link, pointing exactly where it pointed, whether that is a file, a folder,
somewhere absolute, or nowhere. A folder sent up and brought back down is the
folder it was, links included.

**A folder that could not be made on a host said nothing about it.** Uploading
a folder into a place that will not take it — somewhere you have no permission
to write, or where a file already has that name — the folder simply did not
appear, and the transfer still said it had finished. It fails now, and passes
on what the far end said about it. Carrying a folder onto one that is already
there still merges, exactly as before.

Nothing else here is visible from the outside. The suite went from 459 checks
to 466, and both of these are held against OpenSSH's own server rather than a
stand-in — including the one detail nothing else could settle: which way round
that server wants the two paths of a request to make a link.
